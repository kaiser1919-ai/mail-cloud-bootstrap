# Переносимый установщик облака и почты
Подтверждено владельцем 18.10.2026: публичный отдельный репозиторий; мастер максимально автоматический, спрашивает только необходимые параметры.

## Objective
Воспроизвести функциональный конфиг RU-сервера на чистой Ubuntu 24.04 LTS amd64 (основная цель) и Debian 13 amd64 (второй этап, реальная серверная проверка поручена владельцем) без переноса личных данных и без изменений рабочего сервера.

## Requirements
- R1: Терминальный мастер: домен, публичный IPv4, email ACME, количество почтовых ящиков (1–20) и логин каждого отдельно. Для каждого адреса явно показать root-private путь и JSON-ключ его пароля, не печатая пароль. Cloud/mail hostname выводятся из домена; расширенный файл параметров позволяет изменить их и размер пула. Пароли генерируются локально, сохраняются только root-private.
- R2: Нативный стек Nextcloud 34.0.4, Mail, Calendar, Office/Collabora, LDAP, Postfix, Dovecot 2.3 на Ubuntu / 2.4 на Debian, Rspamd, отдельные Redis для почты и облака, MariaDB, PHP-FPM, Nginx, TLS, cron. Общий LDAP-пароль облака и почты; Mail в сессии Nextcloud.
- R3: Общий ограниченный ext4-пул для файлов, почты и состояния фильтра, физическое резервирование, защита от записи при потере mount; ресурсы/временные файлы ограничены. Индикатор фактической общей ёмкости без раскрытия чужих файлов.
- R4: SMTP25 без AUTH, submission587 только STARTTLS, IMAPS993, запрет relay и чужого sender; обязательный milter/DKIM, исходящий лимит 50/час; LDAP/DB/Redis/CODE не публикуются. Отдельный recovery-admin, настройка MFA до открытия портала.
- R5: Мастер проверяет DNS A/MX/SPF/DKIM/DMARC/PTR и сертификаты, выдаёт точные требуемые записи. Не обещает доставляемость, не меняет DNS/хостинг без API-доступа. Обновление TLS с deploy hook.
- R6: Preflight чистой Ubuntu 24.04 / Debian 13, последовательные возобновляемые фазы, блокировка параллельного запуска, запрет перезаписи чужого конфигурационного дерева; повторный запуск не форматирует пул и не меняет пароли. Ошибки не считаются успехом.
- R7: README.md EN / README.ru.md RU: ссылка/команда мастера на первом экране, сразу ниже минимальные системные требования; архитектура, ограничения, исправленные проблемы, эксплуатация/обновления/backup; GitHub CI, локальные тесты, отдельный публичный GitHub-репозиторий с проверкой секретов перед публикацией.

- R8: Автоматически выбирать профиль Ubuntu 24.04 LTS: PHP 8.3, нативные пакеты без PPA, конфигурации Dovecot 2.3/LDAP/TLS и совместимый Postfix. Все PHP helpers/cron/FPM используют выбранный профиль; Ubuntu universe подключается штатно при необходимости. AppArmor сохраняется: локальные разрешения для проектных LDAP-путей и адресное userns-разрешение только CODE AppImage на Ubuntu, без отключения глобальной защиты. Сохранить профиль Debian 13/PHP 8.4/Dovecot 2.4; серверная приёмка Debian выполняется отдельным следующим этапом. Профиль сохраняется, смена ОС/профиля при resume отклоняется. CI проверяет обе ветки шаблонов и нативные парсеры/пакеты Ubuntu в изолированной среде, не production.

- R9: По прямому разрешению владельца 19.10.2026 провести ограниченный стресс-тест пула 80 ГиБ на существующем диске тестовой VPS. Явный флаг `--test-low-headroom` уменьшает только тестовый начальный резерв с 25 до 8 ГиБ, при resume — с 5 до 2 ГиБ; режим сохраняется и не может включаться/выключаться задним числом. Обычные требования не ослаблять. Контроль перед/после фаз: минимум 2 ГиБ вне пула, MemAvailable 250 МиБ, SwapFree 512 МиБ. Не заполнять корневой раздел до отказа; нагрузка только в собственной временной папке внутри ограниченного пула, с очисткой только своих fixtures. Реальную нагрузку/результаты фиксировать отдельно от unit/CI. Ёмкость образа и фактическую доступную ёмкость не смешивать.

- R10: При установке объяснить SWAP и проверить суммарную активную подкачку минимум4ГиБ. Если недостаточно, с отдельным явным согласием предложить создать только недостающий объём, округлённый вверх доГиБ, в root-private файле на ext4/XFS; существующую подкачку не отключать/не форматировать. Учесть файл дополнительно к неизменному резерву пула, отказаться до создания при нехватке места/неподдерживаемой ФС. Без sparse/CoW, права0600, запись в fstab с backup, повтор без дубликатов/нового mkswap; чужие/частичные файлы не перезаписывать. --plan/--check/--open-portal не создают SWAP. Не изменять уже опубликованный Ubuntu release/tag.

- R11: По поручению владельца выполнить реальную приёмку на отдельной чистой Debian13amd64: выбор PHP8.4/Dovecot2.4, помощь с SWAP через мастер, установка/возобновление/полный повтор, reboot с сохранением state/паролей/mounts/файлов, TLS/DNS/локальная двунаправленная почта с DKIM, negative auth/relay/sender/privacy и native Office ODT edit/save/reopen. Исправлять реальные Debian-несовместимости в том же portable repo с регрессиями Ubuntu; Ubuntu tag не двигать. До actualPASS не объявлять Debian проверенным. Нагрузка только собственными тестовыми fixtures; production не менять.

## Constraints
- C1: Не менять production; только новый проект. Не переносить ключи, токены, домены/IP/почту владельца, приватную историю и проприетарные шрифты.
- C2: Без Docker/AIO/Mailcow; чистая Ubuntu 24.04 LTS или Debian 13 amd64, systemd; root нужен только пользователю на целевой машине. Backup внешний не реализован, не обозначать его готовым.
- C3: Никакого автоматического удаления/форматирования существующих данных; пакетные версии из подписанных штатных security-репозиториев выбранной ОС фиксировать в install receipt, архив Nextcloud проверять pinned SHA256, apps — штатной подписью Nextcloud.

## Edge Cases
- E1: Невалидный/инъекционный ввод отклоняется до записи/выполнения.
- E2: DNS/ACME/сеть недоступны — остановка с понятной причиной и возобновление после исправления, без генерации новых паролей.
- E3: Занятые порты/установленный чужой стек/недостаточный диск — отказ до изменения служб.
- E4: Прерывание/повтор/конкурентный запуск — сохранение состояния/секретов, не повторять mkfs; несовпадение параметров/артефактов блокируется.

## Definition of Done
- D1: Локальные tests и syntax/render проверки проходят, нет персональных данных/секретов.
- D2: Реальный clean Ubuntu 24.04 install + повторный запуск + reboot + negative mail/auth/privacy + Office save/reopen проверены; Ubuntu-приёмка зафиксирована отдельным неизменяемым release/tag; реальную проверку Debian 13 по тем же сценариям выполнить отдельным этапом до заявления его готовности; если тестовая VPS недоступна, фиксировать непроверенное и НЕ объявлять готовность.
- D3: Публичный GitHub repo содержит проверенный исходный код, двуязычную документацию и мастер.

## Research and Critique
Исходники: соседний приватный проект «Облако и почта»: deploy, rollout, итог от 14.10 и Office scripts. Не публикуются: индивидуальные grants, диагностика production, токены, Gilroy. Старые deploy helpers привязаны к hostname, путям, датам и состоянию миграции; простая последовательная обёртка непереносима.
Проверены первичные источники 18.10.2026: docs.nextcloud.com/server/latest/admin_manual/installation/source_installation.html; doc.dovecot.org/main/core/config/auth/databases/ldap.html; docs.rspamd.com/modules/ratelimit/. Используем реальные нативные решения существующего внедрения, не меняем стек на AIO.
Риски: 2GB с CODE требует проверки реальной нагрузки; HTTP1.1 для проблемного CDN; Dovecot2.4 несовместим с 2.3; PHP proxy scripts только точечно; /tmp не использовать для CODE архивов; mount dependency, TLS mgr, две Redis, MFA и DNS не пропускать.

## Implementation Plan
1. Переносимый мастер, валидация/состояние/lock; тесты без root.
2. Ansible localhost: storage, native runtime, identity/cloud/mail/TLS/Office; шаблоны и guards.
3. Документация и локальные syntax/render/security/regression tests; coverage и spec-review.
4. Изолированный реальный тест при наличии безопасной VPS; публикация исходников с честным статусом проверки.
